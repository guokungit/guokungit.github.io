    Optional：Java 版的 null 安全 重要
    Java OptionalJava
    // 声明可能不存在的值

    面向对象基础

    Java 是严格的 OOP 语言，一切皆对象。类是模板，对象是实例。

    定义类 = 定义类型 前端类比
    TypeScript前端
    class User {
  name: string
  age: number

  constructor(name: string, age: number) {
    this.name = name
    this.age = age
  }

  greet(): string {
    return `Hi, I'm ${this.name}`
  }
}

const user = new User('Tom', 25)
user.greet()
    JavaJava
    public class User {
    private String name;  // 封装：私有字段
    private int age;

    // 构造器
    public User(String name, int age) {
        this.name = name;
        this.age = age;
    }

    // getter / setter（Java 惯例）
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }

    public String greet() {
        return "Hi, I'm " + name;
    }
}

User user = new User("Tom", 25);
user.greet();
    ⚠️ 注意差异 Java 必须 new 创建对象；基本类型 int / boolean / double 不用 new；Java 没有 ES6 模板字符串，用 + 拼接或 String.format()。

    数组/列表操作对照 前端类比
    JavaScript前端
    const list = [1, 2, 3, 4, 5]

// 遍历
list.forEach(n => console.log(n))

// 映射
const doubled = list.map(n => n * 2)

// 过滤
const evens = list.filter(n => n % 2 === 0)

// 查找
const found = list.find(n => n > 3)

// 判断是否存在

// 归约

    Java Stream APIJava
    List<Integer> list = List.of(1, 2, 3, 4, 5);

// 遍历
list.forEach(n -> System.out.println(n));

// 映射
List<Integer> doubled = list.stream()
    .map(n -> n * 2)
    .toList();

// 过滤
List<Integer> evens = list.stream()
    .filter(n -> n % 2 == 0)
    .toList();

// 查找
Integer found = list.stream()
    .filter(n -> n > 3)
    .findFirst().orElse(null);

// 判断是否存在
boolean has = list.contains(3);

// 归约
int sum = list.stream()
    .reduce(0, Integer::sum);
    💡 Stream API = 函数式编程 Java 8+ 的 Stream API 让你能像 JS 一样链式调用 map/filter/reduce。区别是：必须先 .stream() 开启流，最后 .toList() 收集结果。箭头函数写作 n -> n * 2（不是 =>）。

    Spring 核心概念

    Spring 的灵魂是「控制反转 + 依赖注入」，注解驱动一切。

    依赖注入：Spring 的核心魔法 核心概念
    💡 一句话理解 前端方式：你 import 一个模块，直接调用。
    Spring 方式：你声明「我需要 UserService」，Spring 在运行时把实例塞给你。
    好处：解耦。测试时可换成假的，换实现不改调用方代码。
    前端方式前端
    // 直接 import，紧耦合
import { fetchUser } from './api'
import { db } from './db'

export function getUser(id) {
  const raw = fetchUser(id)
  return db.transform(raw)
}
// 测试时无法替换 fetchUser
    Spring 方式Java
    @Service
public class UserService {
    private final UserRepository repo;
    private final JwtUtil jwt;

    // 构造器注入：Spring 自动传入
    public UserService(UserRepository repo,
                        JwtUtil jwt) {
        this.repo = repo;
        this.jwt = jwt;
    }
}
// 测试时可以传 mock 进去

    @Component
    ≈ Vue 的 provide
    通用组件，注册为 Spring Bean
    @Service
    ≈ composables
    业务逻辑层，本质是 @Component
    @Repository
    ≈ Prisma client
    数据访问层，自动转异常
    @Controller / @RestController
    ≈ Express router
    处理 HTTP 请求，后者返回 JSON
    @Configuration
    ≈ config 文件
    配置类，里面定义 @Bean
    @Bean
    ≈ export const
    方法返回的对象注册为 Bean
    @Autowired
    ≈ inject()
    字段注入（推荐构造器注入代替）
    @Value
    ≈ import.meta.env
    注入配置文件中的值
    Bean 的三种注入方式
    JavaJava
    // ✅ 方式1：构造器注入（官方推荐）

    public UserService(UserRepository repo) {

// ⚠️ 方式2：字段注入（简单但不推荐）

    private UserRepository repo;  // 不能是 final

// ✅ 方式3：通过 @Bean 方法（用于第三方库类）

    @Bean

    Service 层 — 业务逻辑

    Service 是核心业务层，协调 Repository 和其他组件。

    Service 完整示例 ≈ composables/hooks
    JavaJava
    // 1. 定义接口（契约）
public interface UserService {
    LoginResponse login(LoginRequest request);
    User getUserByUsername(String username);
}

// 2. 实现类（具体逻辑）
@Service
public class UserServiceImpl implements UserService {

    private final UserRepository userRepo;
    private final PasswordEncoder passwordEncoder;
    private final JwtUtil jwtUtil;

    // 构造器注入
    public UserServiceImpl(UserRepository userRepo,
                              PasswordEncoder passwordEncoder,
                              JwtUtil jwtUtil) {
        this.userRepo = userRepo;
        this.passwordEncoder = passwordEncoder;
        this.jwtUtil = jwtUtil;
    }

    @Override
    public LoginResponse login(LoginRequest request) {
        // 1. 业务校验
        if (!request.isAgreementAccepted()) {
            throw new IllegalStateException("请先同意用户协议");
        }

        // 2. 查数据库
        User user = userRepo.findByUsername(request.getUsername())
            .orElseThrow(() -> new IllegalArgumentException("用户不存在"));

        // 3. 密码比对（BCrypt 不能用 equals）
        if (!passwordEncoder.matches(request.getPassword(),
                                       user.getPassword())) {
            throw new IllegalArgumentException("密码错误");
        }

        // 4. 生成 token 并返回
        String token = jwtUtil.generateToken(
            user.getUsername(), user.getRole(),
            request.isRememberMe()
        );
        return new LoginResponse(token, user.getUsername(), ...);
    }
}
    Service 层注意事项 避坑
    ⚠️ 不要在 Service 中做这些 ① 不要直接操作 HttpServletRequest/Response（那是 Controller 的事）
    ② 不要返回 HTTP 状态码（业务层不该知道 HTTP 的存在）
    ③ 不要在 Service 里 new 依赖对象（让 Spring 注入）
    ④ 抛业务异常而非返回 null，让全局异常处理器统一处理
    事务管理 重要

        // 扣库存
        inventoryRepo.deduct(order.getProductId());
        // 如果这里抛异常 → 前面 save 自动回滚！
        if (somethingWrong) {
            throw new RuntimeException("失败");
        }
    }

    @Transactional(readOnly = true)  // 只读事务，优化查询
    public List<Order> listOrders() {
        return orderRepo.findAll();
    }
}
    💡 前端类比 事务 ≈ 数据库版的「全有或全无」操作。像 Promise.all 但更安全——中间任何一步失败，前面已执行的 SQL 全部撤销。@Transactional 是声明式的，不用手写 begin/commit/rollback。

    安全与鉴权

    Express 中间件前端
    // JWT 验证中间件
function authMiddleware(req, res, next) {
  const token = req.headers.authorization
    ?.replace('Bearer ', '')

  if (!token) {
    return res.status(401).json({
      message: '未登录'
    })
  }

  try {
    const decoded = jwt.verify(token, SECRET)
    req.user = decoded
    next()
  } catch {
    res.status(401).json({ message: 'token无效' })
  }
}

app.use('/api', authMiddleware)
    Spring Security FilterJava
    @Component
public class JwtAuthFilter
    extends OncePerRequestFilter {

    private final JwtUtil jwtUtil;

    public JwtAuthFilter(JwtUtil jwtUtil) {
        this.jwtUtil = jwtUtil;
    }

    @Override
    protected void doFilterInternal(
            HttpServletRequest request,
            HttpServletResponse response,
            FilterChain chain) {

        String token = extractToken(request);

        if (token != null &&
            jwtUtil.validateToken(token)) {
            // 解析并设置到 SecurityContext
            String username = jwtUtil.getUsernameFromToken(token);
            var auth = new UsernamePasswordAuthenticationToken(
                username, null, List.of());
            SecurityContextHolder.getContext()
                .setAuthentication(auth);
        }

        chain.doFilter(request, response);  // 放行
    }
}
    SecurityConfig — 安全规则配置
    JavaJava
    @Configuration
@EnableWebSecurity
public class SecurityConfig {

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .csrf(csrf -> csrf.disable())              // 关闭 CSRF（JWT 不需要）
            .cors(cors -> cors.configurationSource(corsSource()))
            .sessionManagement(s ->
                s.sessionCreationPolicy(STATELESS))  // 无状态会话
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/auth/login").permitAll()  // 登录公开
                .requestMatchers("/h2-console/**").permitAll()
                .anyRequest().authenticated()           // 其余需认证
            )
            .addFilterBefore(jwtAuthFilter,
                UsernamePasswordAuthenticationFilter.class);
        return http.build();
    }

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();  // BCrypt 加密
    }
}
    💡 关键概念 ① CSRF：跨站请求伪造，JWT API 通常关闭；② 无状态：不存 session，每次请求带 token；③ permitAll vs authenticated：公开 vs 需登录。

    前端转后端常见陷阱

    这些坑 90% 的前端转后端都会踩，提前了解少走弯路。

    陷阱 1： == vs equals() 高频
    🚨 错误写法 if (str1 == str2) — 比较的是对象引用地址，不是内容！
    ✅ 正确写法 if (str1.equals(str2)) — 比较字符串内容。
    或 Objects.equals(str1, str2) — 自动处理 null。
    ⚠️ 例外 基本类型 int / long / boolean 等用 == 是正确的，因为它们不是对象。
    陷阱 2：NullPointerException (NPE) 高频
    🚨 前端没有的痛点 JS 中 null.foo 会抛错但不影响编译。Java 中 null.foo() 抛 NullPointerException 导致请求崩溃。
    ✅ 防御策略 ① 用 Optional<T> 包装可能为空的返回值；
    ② Objects.requireNonNull(obj, "msg") 提前校验；
    ③ Optional.ofNullable(str).orElse("") 给默认值。
    陷阱 3：值传递 vs 引用传递
    ⚠️ 前端误区 JS 中对象是引用传递，函数内修改会影响外部。Java 中对象也是引用，但引用本身是值传递——重新赋值不会影响外部。
    JavaJava
    public void changeName(User user) {
    user.setName("new");  // ✅ 修改对象属性 → 外部可见
}

public void replaceUser(User user) {
    user = new User("other");  // ❌ 重新赋值 → 外部不变
}
    陷阱 4：忘记 @Transactional
    ⚠️ 症状 Service 方法中先 save 再操作另一个表，中间抛异常，发现第一条数据没回滚。
    ✅ 解决 方法加 @Transactional，所有数据库操作在同一事务中，异常自动回滚。只读查询加 @Transactional(readOnly = true)。
    陷阱 5：CORS 跨域
    ⚠️ 症状 前端请求报 CORS error，浏览器 Network 看到 OPTIONS 预检请求 403。
    ✅ 解决 在 SecurityConfig 中配置 CORS： .cors(cors -> cors.configurationSource(...))，允许前端域名、方法、头。Spring Security 6 默认不开 CORS，必须手动配。
    陷阱 6：日志用 println 不用 Logger
    🚨 错误 System.out.println("xxx") — 生产环境无法控制级别，无法输出到文件。
    ✅ 正确 
    private static final Logger log = LoggerFactory.getLogger(MyClass.class);
log.info("用户登录: {}", username);
log.error("登录失败", exception);
    Spring Boot 自带 Logback，支持 DEBUG/INFO/WARN/ERROR 级别，生产环境动态调整。
    陷阱 7：Lombok 依赖
    ⚠️ 症状 看到 @Data / @Getter / @Setter / @Builder 注解但 IDE 报错找不到方法。
    ✅ 解决 Lombok 是代码生成工具，pom.xml 加依赖：<dependency><groupId>org.projectlombok</groupId>...</dependency>。IDE 需安装 Lombok 插件。@Data 自动生成 getter/setter/toString/equals。
    陷阱 8：异步处理差异
    ⚠️ 前端习惯 大量使用 async/await 和 Promise，I/O 默认异步。
    ✅ Java 习惯 Spring MVC 默认同步阻塞（一个请求一个线程），大部分场景不需要 async。需要异步时用 @Async 或 CompletableFuture。虚拟线程（Java 21+）让同步写法也能高并发。
